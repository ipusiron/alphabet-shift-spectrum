# Alphabet Shift Spectrum - 詳細設計書

## 目的

入力へ0～25の全アルファベットシフトを適用し、文字列と頻度を比較する教育用ツールである。統計値は手動分析の観察材料として示し、正しい平文、鍵、言語、暗号方式を自動判定しない。

## 対象

- Caesar暗号
- 鍵長1のVigenère暗号
- 同じ26通りのアルファベット回転として扱える教材

## 構成

- Vanilla HTML/CSS/JavaScript
- 外部ライブラリーなし
- HTTP(S)と`file://`の両方で動作
- 日本語／英語切り替え
- モバイルファースト（600px、900pxで拡張）

## ファイル責務

| ファイル | 責務 |
|---|---|
| `index.html` | 意味構造、CSP、静的な翻訳キー |
| `logic.js` | 正規化、シフト、頻度、参照プロファイル、二項分布、カイ二乗と文字別寄与、感度比較、モンテカルロ、分析記録 |
| `messages.js` | 日本語／英語辞書 |
| `script.js` | 状態、描画、操作、アクセシビリティ |

## 処理

### 1. 正規化

- 文字列を大文字化
- ASCII英字A～Z以外を除外
- 有効英字は20,000文字まで

### 2. 26シフト

各文字インデックスへ`+shift (mod 26)`を適用する。各結果についてA～Zの出現回数を数える。

### 3. カイ二乗順位

```text
χ² = Σ (observed - expected)² / expected
```

選択した参照プロファイルから期待回数を作り、値の昇順で1～26位を付ける。一般英語は固定値、均等分布は各`1/26`、利用者コーパスはA～Zの度数へ各1件を加えて正規化する。同値または浮動小数の加算順だけによる極小差の場合は、シフト番号の昇順とする。

各文字について次の項を保持する。

```text
寄与 = (観測回数 - 期待回数)² / 期待回数
```

26文字の寄与の合計は順位付けに使うχ²と一致する。上位3シフトでは寄与の降順、同値の場合は文字順で上位5文字を表示する。

### 4. 希少文字チェック

J、K、Q、X、Zを対象とし、5文字中で最大の参照頻度`p = 0.00772`を共通の上限として使う。

```text
k = min { k : P(X >= k) <= alpha / 5 }
X ~ Bin(n, p), p = 0.00772, alpha = 0.003
```

二項確率は最頻値を重み1として上下へ漸化式で展開し、総和で正規化する。これにより`(1-p)^n`のアンダーフローを避け、20,000文字まで同じ処理を使う。

1シフト内で5文字を同時に確認するため、Bonferroni補正として各比較へ`alpha/5`を用いる。いずれかの文字数が`k`以上なら「基準超過・要確認」とする。これは候補の除外や正解判定ではない。

### 5. 閾値感度ラボ

利用者が指定した基準標本数について、次の標本数を重複なしで計算する。

```text
round(0.5n), n, min(2n, 20000)
```

すべて1～20,000へ収める。`p`は0より大きく0.5以下、`α`は0より大きく0.2以下、比較数は1～26の整数とする。補正ありでは`α / m`、補正なしでは`α`を各比較へ使う。いずれも通常分析と同じ厳密二項計算を呼び出す。

感度ラボは通常分析の`thresholdInfo`を書き換えない。シフト生成時だけ、比較開始点として基準標本数を有効英字数へ合わせる。

### 6. モンテカルロ比較

基準行の`n`、`p`、`k`を使い、厳密二項分布の累積分布配列から逆変換で標本を生成する。各試行で`n`回のBernoulli試行を反復しないため、計算量は概ね`O(n + trials log n)`とする。

乱数は32ビットのxorshiftで、同じシードと条件なら同じ結果を返す。試行回数は100～20,000、シードは32ビット符号なし整数に制限する。表示するのは厳密上側確率、推定比率、超過回数、絶対誤差である。

感度入力、試行回数、シード、または生成時の標本数同期が変わったら結果を破棄する。対象は1つの二項確率であり、多重比較全体をシミュレートしない。

### 7. 分析概要のコピー

コピー対象は次だけで構成する。

- 有効英字数
- `p`、全体`α`、比較数、基準`k`
- χ²上位5シフトと値
- 希少文字チェックの基準内／基準超過件数
- 正解を証明しないという限界注記

暗号文、シフト後の文字列、個々の文字頻度は含めない。Clipboard APIが利用できない場合は`execCommand('copy')`を試し、それも失敗した場合は同じ概要を選択済みの読み取り専用欄へ表示する。

### 8. 分析記録

`createAnalysisRecord`は次をJSON化可能な値として組み立てる。

- スキーマ名とバージョン
- 入力のA～Z度数と合計文字数
- 参照プロファイルのID、平滑化後の頻度、コーパス文字数
- 希少文字モデルと感度ラボ設定
- 上位5シフト、基準内／超過件数、感度閾値

原文、シフト文字列、利用者コーパス本文は受け取らず、記録へ含めない。`parseAnalysisRecord`は度数と合計、正の参照頻度と総和、モデル値、感度設定を検証する。読み込んだ`result`は信用せず、元の1文字頻度を26通りに回転してカイ二乗順位と希少文字結果を再計算し、正規化した記録を返す。

### 9. ヒートマップ

26行×26列の出現回数を、全セル中の最大値に対する相対比で5段階表示する。各セルには数値とアクセシブルなラベルを併記する。横幅が狭い画面ではヒートマップ内部だけを横スクロールさせる。

## セキュリティ

- 動的文字列は`textContent`で描画
- CSPは自己ホストしたスクリプト／スタイルだけを許可
- 外部通信、外部依存、動的コード評価なし
- 入力長を20,000有効英字へ制限
- コピー概要には入力本文を含めない
- JSON読込は1MBまでとし、動的値は`textContent`で描画
- JSONには原文、シフト文字列、利用者コーパス本文を含めない
- 読み込んだ派生順位を信用せず、検証済み集計値から再計算
